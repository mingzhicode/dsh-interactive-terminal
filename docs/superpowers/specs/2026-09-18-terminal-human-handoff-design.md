# 当前终端操作的人工接手

## 目标与约束

模型在共享 PTY 中启动交互程序后，用户可以显式接手该操作，在同一个 xterm 终端回答问题，不先中断程序，也不把回答排成后续 Shell 命令。每个对话仍独占一个 PTY；只有一个输入写入者；独立操作继续按照接收顺序排队。接手改变当前操作的输入负责人，不是新增操作插队。保留四个模型工具、SIGKILL 的既有限制、固定 PTY 尺寸及官方公共接入方式，不扩展官方 PTY seam，不自动 commit 或发布。

## 方案选择

采用显式接手并复用人工输入租约。用户点击按钮表达接续当前操作的意图，不根据输出中的问号、提示文本或静默时间猜测交互状态。延长超时不能解决输入排在命令完成之后的问题；自动根据键盘输入抢占会混淆新命令与当前程序的回答，因此不采用这两种方案。

## 界面与交接

状态栏显示实际输入负责人。当前控制器连接正常且存在可接手的模型发送操作时，显示“接手输入 / Take over input”。只读连接和移动端不能接手。接手按钮不携带终端输入；收到服务端授权后，焦点进入原 xterm，用户才输入回答。模型占用期间，直接键入或粘贴不会暗中排队保存回答，而是提示先接手，避免超时后把旧回答发送给 Bash。空闲 Shell 的人工输入仍按既有人工租约执行。

请求绑定会话、PTY generation 和服务端发布的当前操作标识。服务端校验控制器身份及目标仍是可交接的模型发送操作；交接过程中保持当前队列位置，不先释放再重新申请。已结束、已被替换、已进入恢复、未完成初始输入投递或已被其他连接接手的目标均拒绝，不降级为普通人工输入。异步交接需要在提交时再次核对目标。接手失败显示明确提示，不发送任何缓存回答。

官方 provider 在 Linux 检测到 stdin_read 并释放模型输入占用后，用户可以按既有空闲输入路径接续前台程序；本功能不依赖该检测能力。官方 macOS provider 无法报告 stdin_read，因此显式接手尤其用于该平台。接手不承诺在任意程序自行退出与按键到达之间实现操作系统级原子性，但必须拒绝已经观察到失效的操作及租约，不能把过期请求应用于队列中的下一项。

## 队列、工具结果与生命周期

交接成功即清除该模型操作的普通超时计时器，并切断原模型调用的取消监听对人工租约的控制。若超时或取消已经先进入恢复，则交接失败；不得撤销已发出的 SIGINT。用户需要在现有默认 30 秒期限内接手，已经被中断的登录程序不能通过接手复活。

原模型工具调用以新增的 waitReason: human_handoff 返回，明确表示人工接手而非程序完成。模型可见结果仍通过正常工具结果写入会话日志；说明要求模型等待用户完成交互，不重复发送回答。输出捕获截至交接，后续读取通过原有 read 工具取得。人工租约的结束与模型工具返回分别管理，模型返回时不能释放当前队列位置或减少仍占用的容量。

接手后复用人工输入的串行写入、输入限额、断线重连及宽限期恢复机制。后续模型发送、信号、重置仍排在当前操作之后，读取不占队列。正常受控 Shell 提示符或会话退出结束人工占用；仅按 Enter 或观察到 stdin_read 不结束人工占用。原操作取消信号不影响已经成功接手的人工输入，但 Agent 销毁仍清理全部资源。

不增加“直接归还模型”按钮，避免在交互程序尚未结束时让排队的新命令充当回答。现有 End Input 明确标注为“中断输入 / Interrupt input”，保持 SIGINT 恢复语义，与无信号的“接手输入”区分。折叠不释放占用；断线超过既有宽限期仍按现有恢复机制处理。

## 实现范围

在插件自有队列和服务层增加原操作的交接及独立结算能力，在自有 Web 协议中传递目标标识及接手请求，使用既有 controller 校验与 HumanLease 管理；不引入依赖、第二个终端、私有进程句柄或第五个模型工具。同步模型结果 schema、工具说明、客户端解析与状态、README 中的交互和平台限制说明。

既有多行输入提前释放、排队重置遇到自然退出失败不因本次变更视为解决，也不借本次修改推广为任意多行批处理完成检测。接手必须有过期标识防护；若现有缺陷阻止本功能的单条交互命令验收，应明确报告而非掩盖。

## 验收

- 队列测试：接手不发信号、不启动下一项；跨越原超时期限仍能输入；原调用取消不再中断人工租约；人工结束后后续操作保持顺序。
- 竞态测试：提示符、超时恢复、取消、重置和退出先发生时，旧接手请求失败；过期人工输入不能落到下一项；失败不保留待发送回答。
- 服务与传输测试：原模型调用返回 human_handoff，队列仍占用；只读或其他控制器不能接手；断线重连及销毁继续清理同一租约。
- 客户端测试：按钮可用性、负责人显示、授权前禁止输入、授权后焦点与输入、中断文案，以及失败时不自动发送缓存内容。
- 真实 PTY 与浏览器测试：使用本地无凭据的交互子进程输出 Y/n 提示，由模型工具启动、浏览器接手并回答，确认回答由子进程读取且之后的模型命令按顺序执行；保持同一 PTY，期间不发送 SIGINT。不使用真实 GitHub 登录完成验收。
- 运行受影响的测试、类型检查、构建与产物检查。报告新增验收和已有失败分别是什么，不以局部通过宣称全插件可发布。现有用户会话及服务保持不动；验证使用隔离实例。

## 当前进度

用户已确认本文设计，实施及独立审查已完成。队列、服务、传输、客户端和工具结果支持显式接手，并在每次人工写入派发前拒绝已经观察到结束的接手租约。构建、类型检查、五项组装 Web/产物/日志检查及两项真实 PTY 接手回归通过。现有多行输入及自然退出后排队重置缺陷仍单独保留；未 commit 或发布，未重启用户原会话。验证详情见 `.superpowers/sdd/reports/handoff-acceptance.md`。
